# Hot — where we left off

Working memory for **session continuity** ([[schema]]): every new session reads this
page FIRST and resumes from **Next steps**; every wrap-up OVERWRITES it with the
latest state. History belongs in [[log]] — this page holds only the CURRENT state.
Keep the four sections below; they are the template.

## Active task
Two things shipped this session: the **neon-HUD UI** ([[ui-design-system]]) and
the **optional trainee profile** ([[trainee-profile]]) — body metrics, current
lifts, injuries, focus groups and a free-text notes box on the new-plan form.
All checks green: lint, `tsc --noEmit`, 103 vitest tests, `npm run build`,
14 wiki tests.

**The LLM path is now live and proven**, which closes the longest-standing gap
in this project. Next up is [[exercise-alternatives]] — designed in full,
decided, not yet written.

## State reached
- **LLM generation works end to end.** The owner configured a key mid-session.
  Plans 3–6 exist in the database; four were generated by DeepSeek. This
  retires "unproven: LLM generation" after weeks on this list.
- **`/plans/[id]` has rendered** for the first time, against real plans.
- **The profile fields demonstrably change the plan**, verified on real
  generations rather than by unit test: "right shoulder impingement" produced
  zero overhead pressing across 21 exercises with shoulder cautions in the
  exercise notes; anchors `{squat 120, bench 85, deadlift 160}` produced
  populated `weightKg` values (bench 80, close-grip 60) where a request without
  anchors left every one of them null; bodyweight 88 → target 80 produced a
  plan titled "…— Cut" with a hold-strength progression paragraph, and the
  number 80 appears nowhere.
- Fixed a bug that only using the form could find: the lift inputs were
  `min={1} step={2.5}`, making 120 a `stepMismatch`, so the form **silently
  refused to submit** — no error, no pending state. All weight fields are now
  `step="any"`. Recorded in [[trainee-profile]].

## Open questions / dissents
- **Measured generation latency is 1–3.5 minutes**, far past the 30–60 s the
  design assumed, and the button just says "Building your plan…" the whole
  time. [[plan-generation]] now carries this; the `streamObject` route handler
  [[plan-pipeline]] specifies is the fix and is still unbuilt.
- **`.env` `DATABASE_URL` may still be wrong.** It was broken at the start of
  this session (`Access denied for user 'hevy'@'localhost'`) and the dev server
  has been running since on an override supplied through the process
  environment. If `npm run dev` fails at boot, this is why — a known-good value
  is `mysql://hevy:hevydev@127.0.0.1:3306/hevy_planner`. The override dies with
  the terminal.
- **No way to clear `excludedExercises`** in the alternatives design. Once the
  feature ships, a swapped-out exercise can never come back. Worth building the
  view/clear UI in the same pass — flagged in [[exercise-alternatives]].
- **Unproven: the live Hevy write path.** Sync has still only run against a
  stub. Irreversible — no DELETE and a routine cap ([[hevy-api]]) — so the
  first real sync must be a 2-day plan, not one of the 4-day plans now sitting
  in the database.
- **Unproven: the container path.** No Docker daemon on this machine
  ([[deployment]]).
- **`data/` still holds the pre-migration SQLite file, likely containing the
  Hevy key IN PLAINTEXT.** Gitignored, not deleted — the owner's call. Flagged
  four times now.
- Hosting undecided (netcup leaning). No backup story; losing `sync_links` is
  the expensive failure ([[hevy-sync]]).
- `.claude/worktrees/e2e-build` is fully merged and redundant; safe to
  `git worktree remove`.
